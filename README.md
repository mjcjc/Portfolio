# 민준기 | 게임 개발 포트폴리오

## PROFILE

처음에는 TCP로 두 플레이어의 화면을 맞추는 것부터 배웠습니다. 블록 게임에서 같은 경기의 승자가 화면마다 다르게 보였을 때, 패킷이 도착하는지만 확인해서는 문제를 풀 수 없었습니다. 서버가 부여한 플레이어 번호가 화면에 표시되기까지 추적하면서, 연결된 기능 사이에서 어떤 값을 기준으로 삼아야 하는지 배웠습니다. 이후에는 IOCP 서버의 송수신 구조를 다루고, 농장 게임에서는 플레이어 이동과 작물·월드 상태를 처리하며 서버가 책임지는 범위를 넓혔습니다. 앞으로는 여러 플레이어가 동시에 행동하거나 연결이 끊겼을 때도 게임 상태가 일관되게 유지되는지 재현하고, 그 결과를 바탕으로 서버 구조를 개선하는 개발자로 성장하고 싶습니다.

## PROJECT

### 랜덤 타워디펜스

**뽑기는 버튼 한 번, 배치는 공격 예고를 본 뒤에.**

싱글플레이 타워디펜스 · Windows PC · Unity/C#  
2026.11 프로토타입 공개 기록 · 플레이 개선 방향 결정, AI 협업, 시연과 테스트 담당

북쪽과 남쪽에서 몰려오는 적을 막아 30웨이브 동안 코어를 지키는 게임입니다. 첫 시연에서는 포탑을 여러 개 뽑으려면 매번 빈칸을 골라야 했습니다. 피드백을 받고 뽑기와 배치를 나눴습니다. 뽑기 버튼을 누르면 포탑이 무작위 빈칸에 바로 놓이고, 어느 길을 막을지는 공격 예고를 확인한 뒤 포탑을 옮겨 결정할 수 있습니다.

Codex에는 자동 배치를 맡기면서 뽑기 비용과 준비 중 이동 규칙을 유지해 달라고 요청했습니다. 여러 포탑이 동시에 공격하는 장면에서는 감속된 적의 발밑에 청록색 원을, 냉각포가 여러 적을 잡았을 때는 명중 지점 위에 한 발 처치 수를 표시하도록 했습니다.

[시연 피드백을 반영한 과정](tower-defense.md) · [전투·합성·AI 예측 설계와 코드](https://github.com/mjcjc/TowerDefense#readme)

### Vida de Granjero

**플레이어의 이동 요청을 받아, 모두가 공유하는 농장 상태로.**

멀티플레이 농장 시뮬레이션 · Windows PC · DirectX 11 클라이언트, C++ 서버  
2026.04 졸업작품 코드 등록 · 2026.09 서버 이동과 월드 동기화 개선 기록  
2인 팀에서 서버 콘텐츠와 클라이언트 연동 담당

팀원이 만든 DirectX 11 클라이언트와 기존 네트워크 코어를 연결했습니다. 서버는 이동 요청을 받으면 순번을 확인하고, 지형과 장애물 조건을 적용해 최종 위치를 정한 뒤에 다른 접속자에게 알립니다. 작물과 월드 오브젝트는 접속 중 공유할 상태와 DB에 저장했다가 복원할 상태까지 다뤘습니다.

연동 중에는 이동 패킷이 도착해도 상대 캐릭터가 움직이지 않았습니다. 로그인부터 이동까지 식별자가 어디에 쓰이는지 따라가 서버 플레이어 ID로 연결 기준을 맞췄고, 두 클라이언트에서 서로의 이동이 올바르게 반영되는지 확인했습니다.

[이동 검증과 연동 과정](vida-de-granjero.md) · [원본 코드](https://github.com/mjcjc/vida_de_granjero)

### TCP 멀티플레이 블록 게임

**같은 경기가 끝났는데, 두 화면에 서로 다른 승자가 떴습니다.**

2인 대전 블록 쌓기 · Windows PC · C++/Win32/Box2D/WinSock2  
2026.09 TCP 서버와 멀티플레이 구현 기록 · 서버 구조, 보드 동기화와 승패 표시 수정, 2클라이언트 검증 담당

두 플레이어가 제한 시간 안에 더 높은 탑을 쌓는 게임입니다. 각 화면이 자기 보드를 같은 내부 번호로 관리해서, 그 번호를 승자 표시에 그대로 쓰면 각자가 가리키는 플레이어가 달라질 수 있었습니다. 서버가 전달한 실제 플레이어 번호를 화면 표시의 기준으로 맞추고, 두 플레이어가 각각 승리하는 상황을 실행해 양쪽 결과를 비교했습니다.

상대 블록이 과거 위치로 돌아가 보이는 문제는 보드 스냅샷의 시퀀스 번호를 확인해 해결했습니다. 수신 스레드는 최신 상태만 저장하고, 화면에 쓰이는 게임 오브젝트는 게임 스레드에서 갱신하도록 역할을 나눴습니다.

[패킷 처리와 승패 동기화 사례](windows-tcp.md) · [원본 코드와 실행 방법](https://github.com/mjcjc/WindowProgrammingTCP#readme)

### 채팅 분산 서버

**송신 큐에서 꺼낸 데이터는 언제 용량에서 빼야 할까?**

멀티 프로세스 채팅 서버 · Windows · C++/WinSock2/IOCP  
2026.07 세션과 송신 큐 작업 · 2026.08 IOCP 전환과 서버 간 채팅 연동 기록  
개인 프로젝트 · 서버 역할 분리, TCP 패킷 처리, 송신 큐와 검증 담당

접속할 서버를 배정하는 MasterServer, 세션과 채팅을 처리하는 GameServer, 채널 간 메시지를 중계하는 WorldServer로 역할을 나눴습니다. GameServer는 연결마다 스레드를 두던 방식을 IOCP 워커가 여러 소켓의 완료 이벤트를 처리하는 방식으로 바꿨습니다.

비동기 송신에서는 큐에서 데이터를 꺼낸 뒤에도 전송이 진행 중일 수 있습니다. 그래서 **대기 중인 데이터와 전송 중인 데이터를 모두 64KB 한도에 포함**하고 완료 이벤트에서 용량을 반환하도록 했습니다. 이 규칙은 동시 입력과 종료 경합 등을 포함한 자동 테스트 27개 항목으로 확인했습니다.

[송신 큐 설계와 검증 결과](server-core.md) · [원본 코드와 테스트 로그](https://github.com/mjcjc/ServerCore)
